## Context

Мотивация и объём — в proposal.md, требования — в `specs/ui-shell/spec.md`. Здесь только то, что
определяет способ.

- Скин собран из слоёв (`layers.css`: `@layer mantine, app`). Правило скина выигрывает у Mantine
  без `!important`. Цвета — только токены из `skin.css`, новых цветов и hex в правилах нет, это
  стережёт `skin-palette.test.ts`.
- Mantine рисует свой фокус через класс `mantine-focus-auto` (`:focus-visible` → `outline`
  цветом primary, то есть жёлтым). У `.mantine-Input-input` outline снят вовсе, а скин
  (`skin-mantine.css:310`) жёстко задаёт рамку поля и не меняет её в фокусе.
- Узел графа FIRS уже рисует фокус так, как рисует игра: `outline: calc(2 * var(--bevel)) dashed
  var(--skin-text)` (`.graph-node[data-focused]`, `skin.css:1024`).
- `SortableTh` вешает `onClick` прямо на `<th>`. Тесты (`capacityColumns.test.tsx`) щёлкают по
  `columnheader`.
- `SavegameFileButton` — это `Button component="label"` с `<input hidden>`. Label не фокусируется,
  а скрытый `display:none` input выпадает из порядка Tab.
- `SettingRow` рисует название и подсказку отдельными `span` без связи с контролом внутри.
  В `SettingsPage.tsx` 41 вызов `Row`/`NestedRow`: 20 Select, 11 Switch, 10 NumberInput. Ещё
  образцы рядов есть в `KitPage.tsx`. Switch в Mantine кладёт input внутрь `<label htmlFor>` без
  текста, поэтому `input.labels.length` у него 1, хотя имени нет. У NumberInput стрелки — это
  `button` с `tabIndex -1` и `aria-hidden`.
- `usePageviews()` вызывается в `App` и отдаёт счётчику `document.title` в момент отправки.
- `--skin-font-small` (FS_SMALL × scale = 9px) носят: подвал (`skin.css:448`), `.intro-reset`
  (`skin.css:648`), `h4` и `.app-header .subtitle` (`skin.css:1582`), в теме — `h4…h6` и `xs`.
- `engine/` не затрагивается. Ни одна настройка `GameSettings` / `CalcSettings` не участвует и
  не меняется — правка только оболочки.

## Goals / Non-Goals

**Goals:**
- Один источник рамки фокуса для всех компонентов, без нового цвета.
- Правки общих компонентов (`SortableTh`, `SettingRow`, `SavegameFileButton`), чтобы
  исправление расходилось по всем вкладкам само.
- Каждое требование спеки закрыто проверкой: юнит-тест (Testing Library) либо визуальная
  проверка на отрисованной странице.

**Non-Goals:**
- Контраст, токены цвета, раскладка форм, тексты вкладок.
- Перекрытие кнопкой импорта липкой панели состава на широком окне — это волна 4 аудита
  (липкая панель с собственной прокруткой).

## Decisions

### D1. Рамка фокуса — пунктир `--skin-text`, одно правило в `skin-mantine.css`

`outline: calc(2 * var(--bevel)) dashed var(--skin-text); outline-offset: var(--bevel)` на:
- `.mantine-focus-auto:focus-visible` (кнопки, вкладки-NavLink, ActionIcon, ссылки Anchor);
- `.mantine-Input-input:focus` — у поля по `:focus`, а не `:focus-visible`: курсор в поле надо
  видеть и после щелчка;
- соседние элементы, которые рисуют скрытые input: `.mantine-SegmentedControl-input:focus-visible
  + .mantine-SegmentedControl-label`, `.mantine-Switch-input:focus-visible + .mantine-Switch-track`,
  `.mantine-Checkbox-input:focus-visible`.

Точные имена классов проверяются по DOM на `/kit` при реализации. Правило фокуса узла графа
остаётся своим, но берёт тот же рисунок.

*Почему так:* это рисунок, которым игра отмечает выбранный виджет, и он уже есть в скине. Цвет
`--skin-text` меняется вместе с `[data-window]`, поэтому рамка видна на любой группе. Черный пунктир
виден и на жёлтой плашке: это цвет её же надписи.

*Отвергнуто:* новый токен `--skin-focus` с отдельным цветом — это смена цвета, которую владелец
запретил, и лишний цвет в палитре. Mantine `focusRing: 'always'` — оставил бы рамку и после
щелчка мышью.

### D2. `SortableTh`: кнопка внутри `th` без своего обработчика

`<th aria-sort={active ? (descending ? 'descending' : 'ascending') : undefined} onClick>` плюс
внутри `UnstyledButton` (`type="button"`) на всю ячейку, без `onClick`. Нажатие Enter/Space на
кнопке даёт нативный `click`, он всплывает до `th`, и срабатывает один такт. Щелчок мышью по кнопке
всплывает так же, а щелчок по полю ячейки ловит сам `th`.

*Почему так:* двойного переключения нет, тесты, щёлкающие по `columnheader`, работают как раньше,
вид заголовка не меняется, если кнопка сброшена в `font: inherit; color: inherit`.

*Отвергнуто:* `tabIndex=0` + `onKeyDown` на `th` — самодельная кнопка без роли; обработчик на кнопке
и на `th` — двойной такт.

### D3. `SavegameFileButton` → `FileButton` Mantine

`<FileButton accept=".sav" onChange resetRef disabled={reading}>{(props) => <Button {...props}
disabled={reading}>…}</FileButton>`. `disabled` передаётся в оба компонента: `FileButton` оставляет
его себе и в `children` не отдаёт, и без явного `disabled` на `Button` кнопка во время чтения
выглядела бы доступной. `onChange` отдаёт `File | null`, `null` игнорируется. Сброс значения,
чтобы тот же файл выбирался повторно, делается через `resetRef` вместо
`event.currentTarget.value = ''`. Визуальные проверки кнопки импорта, которые ищут
`.savegame-launcher label`, переводятся на `button`.

*Отвергнуто:* визуально скрытый input внутри label. Фокус тогда получает невидимый input, и
рамку пришлось бы переносить на label отдельным правилом `:focus-within`, а скринридер всё равно
объявит «поле выбора файла», а не кнопку.

### D4. Кнопка импорта на узком окне — `position: absolute`

`@media (max-width: 700px) { .savegame-launcher { position: absolute; } }`. У кнопки нет
позиционированного предка, поэтому отсчёт идёт от документа: те же `top`/`right`, но кнопка
уходит вместе с шапкой. Место под кнопку в шапке (`--savegame-launcher-width`) уже резервируется
на всех ширинах, так что перекрытия шапки не появится. Порог 700px взят из замеров аудита: на этой
ширине шапка уже переносит строки, а кнопка ложится на текст сводки.

*Отвергнуто:* `absolute` на всех ширинах. Это сломало бы требование «прибита к углу» на десктопе,
которое владелец задал сознательно.

### D5. `SettingRow` связывает названия эффектом по DOM своего ряда

`useId()` для названия и подсказки. `useLayoutEffect` без массива зависимостей находит в
`.setting-control` контролы (`input:not([type=hidden])`, `button`, `[role=switch]`,
`[role=radiogroup]`, `textarea`), кроме `[aria-hidden="true"]` и `[tabindex="-1"]`. Если у
контрола пустое вычисленное имя, эффект ставит ему `aria-labelledby` на название и
`aria-describedby` на подсказку. Имя считается пустым, когда нет `aria-label` и
`aria-labelledby`, а у всех `labels` текст после `trim` пустой. Проверки `labels.length === 0`
мало: у Switch есть пустой `<label>`, обёрнутый вокруг input.

*Почему так:* 41 вызов с тремя разными компонентами плюс образцы на `/kit`. Прокидывать id в
каждый — это 41 место, где можно забыть, и забытое молча останется безымянным. Эффект в одном компоненте
закрывает все строки, включая будущие. React этими атрибутами на чужих узлах не управляет,
поэтому конфликта с рендером нет.

*Отвергнуто:* контекст, который читает каждый контрол, — придётся оборачивать все компоненты
Mantine. Обёртка ряда в `<label>` — label привязывается к одному контролу, а в рядах бывают
сегменты из нескольких радиокнопок.

### D6. Имена полей снабжения и кнопок каталога — через `t()` с параметрами

Новые ключи en/ru. Для полей снабжения — «<название колонки> — <груз>», груз берётся через
`cargoName()` в момент рендера. Для кнопок каталога — «Добавить <машина>» и «Убрать <машина>»,
машина — через `trainName()`. Русские формулировки — по образцу существующих строк вкладки.

### D7. Заголовок документа — эффект в `App`, объявленный до `usePageviews()`

Эффекты одного компонента выполняются в порядке объявления, поэтому к моменту подсчёта просмотра
заголовок уже новый. Название берётся из `TABS` по `pathname`. Для `/game` — имя файла (как в
навигации), для страниц без вкладки (`/kit`) — только название сайта. Зависимости: `pathname`,
`locale`, имя файла.

### D8. `respectReducedMotion: true` в `createTheme`

Mantine сам обнуляет длительности переходов при `prefers-reduced-motion: reduce`. Своих
`transition` и `animation` в скине нет (проверено аудитом).

### D9. Кегль: FS_NORMAL вместо FS_SMALL у читаемого текста

- В `theme.ts`: `h4`–`h6` → `var(--skin-font)`.
- В `skin.css`: подвал (`:448`), `.intro-reset` (`:648`), `h4` и `.subtitle` (`:1582`) →
  `var(--skin-font)`.
- `text-transform: uppercase` у `h4` остаётся: вместе с цветом заголовка он отличает
  подзаголовок от текста.
- Токен `--skin-font-small` и `xs` в теме остаются — для подписей в духе FS_SMALL, если они
  появятся. Сейчас читаемого текста на них не будет.

### D10. Недоступный пункт сегмента — сплошная подложка под надписью

Штриховка `.mantine-SegmentedControl-label[data-disabled]` остаётся. Внутренней обёртке надписи
(`.mantine-SegmentedControl-innerLabel`, класс сверить по DOM) задаётся
`background-color: var(--skin-button)` и небольшой `padding-inline`. Узор остаётся вокруг, буквы
стоят на плашке.

Причина делится на две части:
- **Подсказка при наведении.** Подпись пункта в `OptimizerPage.tsx` оборачивается в `span title`
  с тем же текстом, что в `.goal-hint`.
- **Описание для скринридера.** `title` на `span` описанием радиокнопки не становится, поэтому
  строка `.goal-hint` получает `id` (`useId`). Эффект страницы ставит недоступным
  `.mantine-SegmentedControl-input` ряда целей `aria-describedby` на неё, а когда пункт снова
  становится доступен, атрибут снимает.

Цель Supply бывает недоступна и при заданном выпуске: у груза нет потребителя. Эту причину
страница сегодня не называет, и по спеке ей подсказка не нужна. Новой строки не заводим.

*Отвергнуто:* снять штриховку с сегмента, как у стрелки счётчика. Пункт сегмента — полноразмерная
кнопка, и игра штрихует такие целиком. Mantine `Tooltip` — на недоступном элементе нет событий
указателя, пришлось бы добавлять ещё одну обёртку.

## Risks / Trade-offs

- [Эффект D5 не увидит контрол, смонтированный позже без ре-рендера ряда] → эффект идёт на
  каждом рендере ряда, а смена контрола внутри `children` ре-рендерит ряд. Юнит-тест проверяет
  имена всех контролов вкладки настроек разом (`getAllByRole` без имени → пусто).
- [Пунктир `outline` поля выходит за его габарит и может обрезаться `overflow: hidden` рамки
  таблицы (поля снабжения в ячейках)] → `outline-offset` внутрь для полей в таблицах, если
  визуальная проверка покажет обрезку.
- [`FileButton` меняет DOM кнопки импорта] → существующие визуальные проверки
  `launcher.visual.test.ts` переводятся на новый селектор в том же таске.
- [Порог 700px условный: между 700 и ~900px кнопка может лечь на правый край содержимого при
  прокрутке] → принято. На широком окне правое поле содержимого обычно пустое, случай липкой
  панели состава вынесен в волну 4.
- [Крупный кегль подвала удлиняет его на узком окне] → подвал уже переносится
  (`flex-wrap`), это проверяет `footer-switch.visual.test.ts`.
- [`title` у недоступного пункта на тач-устройстве не показывается] → причина по-прежнему стоит
  строкой `.goal-hint`, так что на тач-экране ничего не теряется.

## Migration Plan

Миграции состояния нет. Выкатка — обычный релиз patch через `make release`, откат — revert коммита.
