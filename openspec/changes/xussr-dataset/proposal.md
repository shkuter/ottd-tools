# xussr-dataset

## Why

Пользователь играет партию с набором xUSSR (JGRPP, 12 GRF), а калькулятор умеет считать
только Iron Horse и ваниль — на главном сейве пользователя он бесполезен. Модель типов
путей (change `track-type-axis`) проектировалась под xUSSR и готова его принять; дизайн
внедрения согласован целиком (память `xussr-set.md`, сессия 29.08.2026), это первый из
трёх запланированных change'ей (данные → составность → рейтинг станций).

## What Changes

- **BREAKING** (persist): настройка `game.ironHorse: boolean` заменяется на
  `trainSet: 'vanilla' | 'iron_horse' | 'xussr'` — взаимоисключающий выбор набора машин;
  миграция стора переводит сохранённое значение.
- Новый экстрактор `pipeline/extract_xussr.py`: `.pnml` → препроцессор C (`gcc -E -C -P
  -x c`) → `.nml` → AST пакета `nml` → `xussr_trains.json`. Пин `XUSSR_REF` в Makefile
  (хеш HEAD заброшенного репозитория). Параметры GRF — дефолты набора, записываются в
  `meta`. Наборы без исходников (Subways, Ivolga) не извлекаются — ограничение в README.
- Таблица путей xUSSR: скоростные классы (60/100/140/250 км/ч) × род тока (автономные,
  25 кВ AC, 15 кВ AC, 3 кВ DC, 1,5 кВ DC), плюс видимый двухсистемный `ER2S`; ванильные
  `RAIL`/`ELRL` набор прячет (HIDDEN). У railtype появляется поле «рода тока» — список в
  порядке набора, — и мощность машины выбирается по нему, а не по эвристике «OHLE, если
  есть catenary». Двухсистемная машина — это машина с мощностью под два источника; путь
  с двумя родами тока — это отдельно, и он у набора есть.
- Вместимость вагона xUSSR зависит от груза (`min(тоннаж, объём × плотность)`) — в данных
  карта «груз → вместимость», расчёты читают её по перевозимому грузу.
- Расход: ветка «только построен» (сумма шести статей — число из меню покупки); в
  `basecost_shifts` добавляется `running_electric` (у Iron Horse и ванили — 0).
- Каталог: buy-menu-спрайты, нарезанные из png исходников; русские имена машин из
  `lang/russian.lng` набора (механизм словарей как `railtypes.ru.json`).
- Импорт сейва: GRFID наборов xUSSR распознаются и включают `trainSet: 'xussr'`; над
  списком изменений — баннер «обнаружены такие-то NewGRF».
- Откат выбранного пути при смене набора идёт на первый выбираемый путь набора, а не на
  лейбл `RAIL` (у xUSSR `RAIL` скрыт).

## Non-goals

- Модель составности (норма сцепки, штраф −15 %, предупреждения) — следующий change
  `xussr-consist-rules`.
- Рейтинг станций по формуле набора (`enable_new_ratios`) — change `xussr-station-rating`;
  здесь фиксируется только решение «это будет настройка `GameSettings`».
- Падение скорости с возрастом машины и скорость вагона от загрузки — не моделируются,
  явно в ограничения.
- Subways Set и Ivolga Addon — исходников нет в репозитории набора.
- Одновременное включение двух NewGRF-наборов (Iron Horse + xUSSR) — выбор
  взаимоисключающий: basecost-шифты одного набора на весь расчёт.

## Capabilities

### New Capabilities

- `train-sets`: выбор активного набора машин как единая настройка партии — три
  взаимоисключающих значения (ваниль, Iron Horse, xUSSR), миграция сохранённого булева
  флага.
- `xussr-dataset`: данные набора xUSSR — извлечение машин, путей и таблицы вместимостей из
  NML-исходников, схема данных (род тока, вместимость по грузу), пин версии, ограничения
  охвата.

### Modified Capabilities

- `track-types`: railtype несёт рода тока, которыми питает; по ним выбираются и мощность
  машины, и её предел скорости, если набор объявил его на каждый род тока; откат
  неизвестного выбора — на первый выбираемый путь набора.
- `pricing`: шифт `running_electric` в `basecost_shifts` — электрокласс перестаёт брать
  дизельный шифт.
- `localisation`: русские имена машин из локали самого набора — словарь имён машин.
- `savegame-import`: распознавание GRFID xUSSR, автовыбор набора, баннер обнаруженных
  NewGRF.
- `savegame-tab`: путь под составом из сейва выбирается не только по тому, где состав
  работоспособен: сперва по мощности (многосистемная машина не читается на чужой ток),
  затем по лимиту скорости — набор со скоростными классами пути иначе считался бы по
  самому медленному.
- `ui-shell`: набор машин перестаёт быть переключателем «Iron Horse вкл/выкл» и становится
  взаимоисключающим выбором из трёх — при том, что раздел наборов остаётся одним, а FIRS
  и Base Costs остаются переключателями.

## Impact

- **Ожидаемый разряд**: minor (0.x: новый набор данных + ломающая миграция persist —
  по правилам проекта до 1.0.0 ломающее изменение поднимает minor).
- `pipeline/`: новый `extract_xussr.py` (+ русские имена в `extract_firs_ru.py` или рядом),
  `grf_sprites.py` не нужен — спрайты из png исходников; Makefile: `XUSSR_REF`,
  `fetch-xussr`, цели data.
- `web/src/`: `types.ts` (схема Train/Railtype), `dataset.ts` (`activeTrains` и родня),
  `engine/tracktypes.ts` (источник питания), `engine/costs.ts` (`running_electric`),
  `engine/consist.ts`/`trip.ts`/`optimize.ts`/`purchase.ts` (вместимость по грузу),
  `state/settingsStore.ts` (миграция `trainSet`), `features/settings/` (селектор набора),
  `savegame/registry.ts`+`import.ts` (GRFID, баннер), i18n-словари.
- Тесты: эталоны из меню покупки игры пользователя (`pipeline/tests/test_xussr_extraction.py`
  — рядом с остальными проверками набора, а не в общем `test_known_values.py`),
  кейс `settings-effect.test.ts` для `trainSet`, тест уникальности id по всем GRF,
  `locales.test.ts` покроет новые словари.
- Источник истины чисел: исходники xussrset на пине `XUSSR_REF` (репозиторий
  George-VB/xussrset, HEAD `100716f9`), сверка — скриншоты меню покупки JGRPP-партии
  пользователя; механика путей — `vendor/openttd/src` (как в `track-type-axis`). Правило
  «не заданный шифт цены равен нулю, а не шифту соседнего класса» (отсюда
  `running_electric`) — `vendor/openttd/src/newgrf.cpp`, действие 0x08, и
  `economy.cpp::RecomputePrices`. На текущих данных эта правка не меняет ни одного числа:
  у Iron Horse нет машин с `RUNNING_COST_ELECTRIC`, у ванили все шифты нулевые.
