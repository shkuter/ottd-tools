## Why

Оптимизатор «Лучший поезд для задачи» умеет отвечать только на вопрос «что выгоднее».
Но не всякий груз возят ради денег: сырьё для собственной цепочки предприятий нужно вывозить
максимально полно — каждый недовезённый процент режет выпуск завода на другом конце. Сейчас
такой ответ из таблицы не достаётся: колонка «Вывоз» есть, но выдача ранжируется по прибыли,
а число поездов берётся минимальным, лишь бы покрыть поток.

Вдобавок деньги на вкладке считаются по полному выпуску предприятия, хотя игра отдаёт станции
только долю `(рейтинг + 1) / 256`. Строки с рейтингом 40 % и 90 % завышены по-разному, поэтому
их прибыли несопоставимы — а при сортировке по вывозу это расхождение становится видимым.

## What Changes

- Вкладка получает выбор **цели поиска**: «Прибыль» (текущее поведение) или «Вывоз».
- **BREAKING** Доход рейса умножается на долю вывоза, когда производство задано. Те же входные
  данные дают меньшие деньги — ровно ту их часть, которую предприятие реально отдаёт станции.
  Действует при обеих целях: доля доставки не зависит от того, что пользователь сортирует.
- **BREAKING** Деньги в таблице (покупка, содержание, прибыль за год) показываются на весь
  **парк** — столько составов, сколько показано в строке, — а не на один состав. Иначе строки
  с разным числом поездов несравнимы.
- Поток делится между поездами парка: лишний поезд не добавляет груза, когда выпуск уже
  вывозится, а расходы растут. Поэтому окупаемость с ростом парка ухудшается, и при равном
  вывозе выигрывает меньший парк.
- При цели «Вывоз» появляется поле «Поездов не больше N» (по умолчанию 4). Оптимизатор
  перебирает число поездов от минимума до N и все длины состава, а не только полную станцию.
- При цели «Вывоз» добавляется колонка с абсолютным вывозом (единиц в год); процентная колонка
  остаётся.
- При `Производство = 0` цель «Вывоз» недоступна: без потока рейтинг не определён.
- Подсказка вкладки честно проговаривает допущения модели и то, что вкладка «Доход рейса»
  считает один состав по полному потоку и с оптимизатором не сойдётся.

### Non-goals

- Не меняется вкладка «Доход рейса»: производство там не задаётся, доля вывоза не считается,
  расхождение с оптимизатором остаётся и просто документируется.
- Не моделируется маршрут из нескольких типов составов, подвоз с промежуточных станций,
  cargodist, статуя в городе и старение поезда.
- Не трогается сама формула рейтинга станции (`engine/rating.ts`): неподвижная точка по
  ждущему грузу там уже есть, эталон реальной партии остаётся в силе.
- Не меняется физика: состав по-прежнему считается полностью гружёным и ждёт полной загрузки;
  доля доставки режет только деньги.

### Ожидаемый разряд semver

**minor** (0.5.0 → 0.6.0). По правилам проекта изменение чисел при том же вводе — это major,
но пока версия 0.x ломающее изменение поднимает minor. Запись в `CHANGELOG.md` помечается
`**BREAKING**`. Сохранённое состояние в localStorage не сбрасывается: в `optimizerStore`
только добавляются поля, недостающие берутся из начального состояния.

### Источник истины

Формулы не выводятся заново, а связываются уже проверенные:
- доля доставки — `vendor/openttd/src/station_cmd.cpp`, `MoveGoodsToStation` умножает выпуск
  на `rating + 1`, `UpdateStationWaiting` сдвигает на 8 бит; это уже реализовано в
  `web/src/engine/rating.ts` и сверено с реальной партией
  (`web/src/engine/__tests__/rating.test.ts`, 72 % перевезено в игре против 0.696 расчётных);
- монотонность вывоза по числу поездов следует из `UpdateStationRating`: короче интервал —
  выше слагаемое времени с последней погрузки и меньше ждущая куча.

## Capabilities

### New Capabilities

- `train-optimizer`: перебор связок «локомотив + вагоны» под задачу и ранжирование выдачи —
  цель поиска, что перебирается, как выбирается строка на локомотив, чем ограничен парк.

### Modified Capabilities

- `route-economics`: доход рейса умножается на долю вывоза; деньги на вкладке оптимизатора
  относятся к парку; требование «Единая модель во всех вкладках» сужается до случая, когда
  производство не задано.

## Impact

- `web/src/engine/trip.ts` — новый параметр `deliveredShare` (по умолчанию 1), множитель дохода.
- `web/src/engine/optimize.ts` — цель поиска, перебор длин и числа поездов, деньги парка,
  ранжирование и тай-брейки.
- `web/src/state/optimizerStore.ts` — поля `goal` и `maxTrains` (persist).
- `web/src/features/optimizer/OptimizerPage.tsx` — переключатель цели, поле N, новая колонка,
  блокировка цели при нулевом производстве, подсказки.
- `web/src/i18n/en.json`, `ru.json` — новые строки.
- `web/src/engine/__tests__/` — тесты на урезание дохода, порядок выдачи по цели, обрезку по N,
  деньги парка.
- `CONTEXT.md` (новый) — глоссарий: поток, доля вывоза, вывоз, парк.
- `docs/adr/` — решение «доход режется долей доставки, поток и физика остаются полными».
