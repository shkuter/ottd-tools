## Context

`components/` уже существует и содержит презентационные мелочи (`Money`, `Warning`, `format`),
так что место для общих компонентов в проекте определено — просто `TrainImage`/`CargoIcon`
оказались не там. Оба компонента без состояния, зависят только от `import.meta.env.BASE_URL`
и от классов в `index.css`.

## Goals / Non-Goals

**Goals:**
- Импорты между вкладками исчезают полностью.
- Каждый общий компонент — свой файл, как `Money.tsx` и `Warning.tsx`.

**Non-Goals:**
- Разбор больших страниц на подкомпоненты (`SettingsPage` 430 строк и т. п.).
- Вынос бизнес-логики из компонентов — отдельный change.

## Decisions

**Отдельные файлы, а не общий `components/index.tsx`.** Проект уже держит по компоненту на
файл; общий бочонок-индекс ломал бы этот порядок и делал бы дерево импортов менее очевидным.

**Мёртвый код удаляется, а не помечается `@deprecated`.** История git — достаточный архив,
а `accelSimulation()` (47 строк потиковой симуляции) не вызывается даже тестом, то есть его
корректность сейчас ничем не подтверждена; хранить непроверяемый код в движке хуже, чем
достать его из истории, когда появится вкладка, которой он нужен.

## Risks / Trade-offs

- **Удалили то, что кому-то нужно** → всё удаляемое проверено grep'ом по `web/src` на предмет
  использования; после правки `tsc --noEmit` и полный прогон тестов.
- **Классы CSS остаются в `index.css`** → это верно и сейчас: компоненты и раньше не носили
  свои стили с собой, менять эту схему в рамках переезда не нужно.
