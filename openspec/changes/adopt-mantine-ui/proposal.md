## Why

Интерфейс собран из голого HTML и 1100 строк ручного CSS (`index.css` + `skin.css`): селекты,
свитчи, числовые поля, табы и таблица каталога написаны и стилизованы вручную, а поведение,
которое пользователь ждёт от таких контролов (поиск в выпадающем списке, клавиатура, фокус,
подсказки, всплывающие сообщения), либо отсутствует, либо держится на самописных кусках вроде
`input-switch-polyfill`. Дальше расти так дорого: каждая новая панель — это ещё порция CSS,
которую надо руками свести с пиксельным скином OpenTTD.

Mantine 9.5.1 даёт готовый набор компонентов с peer-зависимостью ровно на React 19.2, который
стоит в проекте, и — главное — темизируется через CSS-переменные, то есть его можно целиком
подчинить существующим токенам `--skin-*`, не отказываясь от вида игры.

## What Changes

- Подключить Mantine: `@mantine/core`, `@mantine/hooks`, `@mantine/notifications`,
  `@mantine/charts` (+ `recharts` как peer). `MantineProvider` с собственной темой — в `main.tsx`.
  `@mantine/form` — под вопросом: настройки остаются в `settingsStore`, а для локального состояния
  страниц польза проверяется на шаге фильтров каталога; не подтвердится — пакет не ставим.
- Перевести весь UI на компоненты Mantine: все пять вкладок (`features/*`), общие компоненты
  (`components/*`), шапка, навигация и подвал `App.tsx`. Разметка страниц переезжает на
  layout-примитивы (`Stack`, `Group`, `Grid`, `Paper`, `Table`), собственный CSS сокращается до
  темы и точечных правок.
- Тема Mantine выводится из уже существующих токенов скина: палитра OpenGFX2 из
  `data/opengfx2_palette.json`, шрифт `OpenTTD Sans`, нулевое скругление, бевели 2px. Вид
  приложения на экране не меняется — меняется только то, из чего оно собрано.
- Каталог машин переезжает с `@tanstack/react-table` на `mantine-datatable` 9.4.0: заголовки с
  сортировкой, закреплённые колонки, пагинация и пустое состояние — готовые.
  `@tanstack/react-table` уходит из зависимостей.
- Каталог перестаёт обрезаться первыми 400 строками: все 1648 машин, подходящие под фильтр,
  доступны через встроенную пагинацию. Это единственное видимое изменение поведения в миграции.
- График дохода на вкладке «Доход рейса» — сейчас самодельный SVG-путь в `RoutePage.tsx` —
  заменяется на `LineChart` из `@mantine/charts`.
- Предупреждения (инфляция, ошибка GRF) переводятся на `Alert`/`notifications`, компонент
  `Warning` либо становится обёрткой над `Alert`, либо исчезает.
- `input-switch-polyfill` удаляется: `Switch` из Mantine работает во всех браузерах сам.
- **Не выбран** `mantine-react-table`: пакет заброшен (последняя публикация 17.02.2025), его
  latest 1.3.4 требует Mantine 6 и Emotion, бета 2.0.0-beta.9 — Mantine ^7.9. Совместимой
  с Mantine 9 версии нет.

## Non-goals

- Не трогаем расчёт: `engine/*`, пайплайн, JSON в `web/src/data/` остаются как есть. При том же
  вводе калькулятор обязан выдавать те же числа.
- Не меняем `state/*` и формат сохранённого состояния — localStorage у пользователя не сбрасывается.
- Не меняем смысл строк в `i18n/*.json`: словари правятся только если появляются новые ключи UI.
- Не заменяем граф FIRS — он рисуется graphviz-wasm в SVG и остаётся своим.
- Не добавляем светлую тему, второй скин и переключатель скинов: скин остаётся один, пиксельный.
- Не переводим приложение на компонентные тесты — их сейчас нет, и заводить `@testing-library`
  в рамках этого изменения не будем (см. риски в design.md).

## Capabilities

### New Capabilities
- `ui-shell`: оболочка интерфейса — из чего собраны элементы управления, как они выглядят
  (скин OpenTTD) и что обязаны сохранять при смене реализации: локализованные подписи, форматы
  чисел по локали, сохранённое состояние, поведение каталога машин.

### Modified Capabilities
- нет: требования `pricing`, `route-economics`, `localisation` и `vanilla-dataset` не меняются —
  меняется только то, какими элементами интерфейс их показывает.

## Impact

- **Разряд semver: patch.** По правилам проекта: тот же ввод даёт те же числа, localStorage не
  сбрасывается, новых вкладок, настроек, наборов данных и языков не появляется — это «полировка
  UI и рефакторинг с теми же числами». Если по ходу работ выяснится, что миграция меняет
  сохранённое состояние или числа, разряд поднимается до major и это обсуждается отдельно.
- **Зависимости.** Плюс: `@mantine/core`, `@mantine/hooks`, `@mantine/notifications`,
  `@mantine/charts`, `recharts`, `mantine-datatable`, `clsx` (peer datatable) и, возможно,
  `@mantine/form`. Минус: `@tanstack/react-table`, `input-switch-polyfill`. Бандл вырастет —
  величину замеряем на `make build` до и после.
- **Код.** `web/src/main.tsx`, `web/src/App.tsx`, все `web/src/features/*/`,
  `web/src/components/*`, `web/src/index.css` (644 строки), `web/src/skin.css` (459 строк),
  новый модуль темы рядом со `skin.ts`.
- **Формулы и данные не затрагиваются**, поэтому источник истины по игре здесь не нужен: значения
  берутся из тех же модулей `engine/*`, что и сейчас, а их эталоны уже закреплены в
  `pipeline/tests/test_known_values.py` и `web/src/engine/__tests__/`.
- **Риск.** Компонентных тестов нет, регрессию вёрстки автотесты не поймают: проверка — глазами
  в браузере (chrome-devtools) по каждой вкладке, плюс `make verify`.
