## Decisions

**Кривая оплаты живёт в `engine/income.ts`, а не в отдельном модуле.** Это та же формула
`transportedGoodsIncome`, просто протабулированная по дням; правило масштаба оси X
(«охватить начало спада: `p1 + min(p2, 120)/2` периодов, но не меньше 2.5× текущего времени
и 50 дней») — тоже про оплату, а не про SVG. Возвращает `{days, income}[]`.

**`chainNodes` — в `features/firs/`, а не в `engine/`.** Это не игровая формула, а обход
данных для подсветки; движок держим для формул. Прецедент — `features/optimizer/doubtful.ts`.

**`economyIdForCargo` — в `dataset.ts`.** Именно `dataset.ts` уже отвечает за переключение
NewGRF/ваниль (`activeCargos`, `canCarryIn`), ключ `'VANILLA'` — тоже его зона.

**`state/index.ts` только регистрирует сторы для сброса.** Не бочонок реэкспорта всего:
единственная функция `resetPersistedState()` вызывает `persist.clearStorage()` у каждого
стора из списка и `reset()`/`clear()` там, где они есть. Список сторов один — добавляя стор,
дописываешь его туда, а не в `SettingsPage`.

**Затрагиваемые модули engine/:** `income.ts` (новая функция), `consist.ts` (замена
инлайна на `internalToMph`). Настройки, участвующие: те же, что у `transportedGoodsIncome`
(`cargoAgingRate`, `jgrpp`, `paymentAlgorithm`) — теперь явно в сигнатуре `incomeCurve`.

## Risks / Trade-offs

- **График изменится визуально** → нет: те же 120 точек, тот же диапазон; проверить в
  браузере глазами до/после.
- **`resetPersistedState` забудет новый стор** → список в одном файле рядом со сторами;
  тест-регистр не делаем (сторов шесть).
