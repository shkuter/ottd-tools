## Context

Импорт `iron_horse` работает только после `os.chdir(IH_ROOT)` и подмены `sys.argv` (Iron
Horse читает аргументы командной строки при импорте). Поэтому бутстрап нельзя вынести в
обычную функцию, вызываемую после импортов, — но можно в функцию, которая **выполняет импорт
внутри себя** и возвращает модули.

## Decisions

**`bootstrap_iron_horse()` возвращает namespace с модулями** (`iron_horse`, `global_constants`,
`DocHelper`, `polar_fox_constants`, `render_docs` по флагу). Вызывающий пишет
`ih = bootstrap_iron_horse()` вверху модуля и использует `ih.iron_horse`. Так порядок
«chdir → argv → path → import» существует в одном месте, а `# noqa: E402` исчезают.

**`requirements.txt` с точными версиями** из текущего venv (`pip freeze` по трём пакетам и
их зависимостям), чтобы `make venv` был воспроизводим.

**`schemas/` удаляем, а не заполняем.** JSON-схема дублировала бы TS-типы `web/src/types.ts` и
инварианты `validate.py`; если понадобится — отдельное решение.

**Затрагиваемые модули engine/:** нет.

## Risks / Trade-offs

- **Бутстрап через функцию меняет момент импорта** → он всё равно на уровне модуля (первая
  строка после `from common import …`), поведение то же. Проверка — `make data` даёт пустой
  диф в `web/src/data`.
