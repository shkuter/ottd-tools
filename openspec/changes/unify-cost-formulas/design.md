## Context

Три копии денежной формулы (см. proposal.md — Why) отличаются только тем, откуда берут
`TrainsMeta`: движковые копии получают её аргументом, копия в `ConsistPage.tsx` импортирует
`trainsMeta` из `dataset.ts` напрямую. Слой `engine/` в проекте — чистые функции без импорта
сторов и данных, это правило нужно сохранить.

`engine/costs.ts` сейчас ничего не знает про `Train`, `TrainsMeta` и настройки: он оперирует
голыми числами (`costFactor`, `grfShift`, множители). Именно поверх этого «сырого» слоя и
написаны три копии — каждая переводит машину и настройки в аргументы `buyCost`/`runningCostPerYear`.

## Goals / Non-Goals

**Goals:**
- Один перевод «машина + настройки → деньги» на весь проект.
- `engine/costs.ts` остаётся чистым: без импортов из `state/` и `dataset.ts`.
- Числа не меняются ни на монету.

**Non-Goals:**
- Сверка формул с исходниками игры (следующий этап работы).
- Приведение других дублей (экономика рейса, конверсия скорости) — отдельные changes.

## Decisions

**Новые функции живут в `costs.ts`, а не в `consist.ts`.** Слой цен — это `costs.ts`;
`consist.ts` про физику и агрегацию состава и сам станет потребителем. Альтернатива —
положить `consistMoney()` в `consist.ts` рядом с `consistStats()` — отвергнута: тогда
`ConsistPage` и `optimize.ts` тянули бы деньги из модуля про физику.

**Сигнатуры принимают доменные объекты, а не числа:**

```
trainBuyCost(train, meta, game, calc)          -> number
trainRunningCostPerYear(train, meta, game, calc) -> number
consistMoney(entries, meta, game, calc)        -> { buy, running }
```

`meta` передаётся аргументом (не импортируется из `dataset.ts`) — так `engine/` не зависит от
данных и функции остаются тестируемыми на синтетических машинах. Существующие «сырые»
`price()`, `buyCost()`, `runningCostPerYear()` остаются экспортированными: на них написаны
тесты, сверенные с игрой, и они выражают саму формулу `GetPrice`.

**Выбор шифта — внутри новых функций.** Правила «движок → `build_engine`, вагон →
`build_wagon`», «STEAM → `running_steam`, иначе `running_diesel`» сейчас продублированы во всех
трёх копиях; они переезжают в `costs.ts` как единственное место. Оговорка про электрический
running-класс (базовая цена электрическая, шифт дизельный) фиксируется комментарием и спекой.

**Множитель длины дня остаётся в содержании.** Все три копии домножают running cost на
`effectiveDayLength(game)`; новая функция делает то же самое, чтобы числа не поехали. Верность
самого допущения — вопрос этапа сверки формул, в спеке он помечен как поведение, а не как истина.

## Risks / Trade-offs

- **Тихое изменение чисел при переносе** → до правки снимается снимок значений (несколько
  реальных машин и составов при разных настройках), после правки сверяется. Плюс уже
  существующие `settings-effect.test.ts` (25 кейсов «настройка меняет расчёт») и эталоны цен
  в `engine.test.ts`.
- **`costs.ts` начинает знать про `GameSettings`** → зависимость на `engine/settings.ts`
  односторонняя (settings не импортирует costs), цикла нет; `consist.ts` и `optimize.ts` уже
  так делают.
