## Context

Мотивация и цифры расхождения — в `proposal.md`, требования — в `specs/localisation/spec.md`.
Здесь важны три ограничения текущего кода.

1. `web/src/i18n/cargos.ru.json` и `industries.ru.json` ведутся руками и никак не связаны с
   `vendor/`. Единственная страховка — `web/src/i18n/__tests__/locales.test.ts`, который ловит
   отсутствующий ключ, но не расхождение с игрой.
2. Словарь грузов ключуется по лейблу (`STBL`), а лейбл не уникален между наборами: `WOOD` — это
   ванильный `wood` («Древесина») и FIRS-груз `logs` («Брёвна»). По лейблу они неразличимы, по id —
   различимы (пересечение id между наборами есть, но названия там совпадают).
3. Соответствие «элемент → id строки» знает только сам FIRS: `cargo.type_name` и
   `industry.get_property("name", economy)`, распакованные через
   `utils.unwrap_nml_string_declaration()` (`vendor/firs/src/docs/doc_helper.py:30,71`).
   Наивная схема `STR_CARGO_NAME_<id.upper()>` теряет пять названий: `seals_belts_and_hoses`,
   `pipe_shop`, `petrol_pump`, `steel_forge_and_foundry`, `fishing_grounds`.

Модули `engine/` изменение не затрагивает, `GameSettings` / `CalcSettings` в нём не участвуют:
язык живёт в отдельном `state/localeStore.ts` именно потому, что не влияет на расчёт.

## Goals / Non-Goals

**Goals:**

- Словари русских названий становятся сгенерированным артефактом с пиннутым источником, как
  `web/src/data/*.json`.
- Расхождение сгенерированного и закоммиченного содержимого обнаруживается командой, а не глазами.
- Ручные правки поверх источника переживают перегенерацию и умирают, когда источник их исправил.

**Non-Goals:**

- Не вводим общий механизм переводов данных «на будущее» (Iron Horse, другие языки) — сейчас есть
  ровно один внешний перевод и один язык кроме английского.
- Не переносим `en.json` / `ru.json` (UI-строки) в генерацию: они пишутся под интерфейс, а не
  под данные.
- Не храним копию `russian.toml` в репозитории: `vendor/` не коммитится.

## Decisions

**Источник тянем одним файлом по sha, а не клоном форка.** Форк ChronosXYZ/firs-ru — это полная
копия FIRS с 7400 коммитами, а нужен один файл на 43 КБ. `Makefile` получает
`FIRS_RU_REF ?= 61a0f0973c…` (полный sha) и цель, скачивающую
`raw.githubusercontent.com/ChronosXYZ/firs-ru/$(FIRS_RU_REF)/src/grf/lang/russian.toml`
в `vendor/firs-ru/russian.toml` — тем же приёмом, что `fetch-opengfx2` тянет базовый набор
графики. Альтернатива — `git clone --depth 1 --branch russian-translation` — отвергнута:
shallow-клон по имени ветки не пинит версию (ветка уедет и перевод молча изменится), а пиннить
через `git fetch --depth 1 origin <sha>` ради одного файла дороже, чем `curl`.

**Отдельный экстрактор, а не расширение `extract_firs.py`.** `pipeline/extract_firs_ru.py`
импортирует `firs` тем же приёмом (подмена `sys.argv` / `os.chdir` до импорта — порядок строк
значим) и пишет только словари в `web/src/i18n/`. Альтернатива — дописать русские имена полями в
`cargos.json` / `industries.json` — отвергнута: данные должны оставаться языконезависимыми, иначе
второй язык раздувает каждый элемент, а `meta` перестаёт описывать один набор данных.

**Разрешение строки идёт через FIRS, а не через угадывание ключа.** Экстрактор для каждого груза
и предприятия получает id строки у самого FIRS, затем:

- `STR_*` → значение из `vendor/firs-ru/russian.toml` (простой парс `[KEY]` + `base = "…"`;
  формат — TOML с одним полем, полноценный парсер не нужен, но `tomllib` доступен в 3.12+);
- `TTD_STR_*` → снять префикс `TTD_` и взять из `vendor/openttd/src/lang/russian.txt`, отбросив
  маркер рода `{G=…}`; падежные ключи (`.gen`, `.acc`) игнорируются — интерфейсу нужен
  именительный.

Ванильный набор переводится тем же вторым путём: `extract_vanilla.py` уже разрешает имена
через `STR_CARGO_PLURAL_*` английской локали игры, поэтому английское имя в данных
однозначно указывает на ключ (совпадений значений в локали нет — неоднозначность роняет
экстрактор).
Альтернатива — таблица исключений «id → ключ» в экстракторе — отвергнута: она правильна ровно до
следующего обновления FIRS, а `type_name` правилен всегда.

**Ключ словаря грузов — `id`, плюс карта `labels`.** Формат:

```json
{ "names":  { "steel_billets_and_blooms": "Стальные заготовки", "logs": "Брёвна", "wood": "Древесина" },
  "labels": { "STBL": "steel_billets_and_blooms" },
  "units":  { "tonnes": "т" } }
```

`names` покрывает оба набора (id уникальны в пределах набора, а совпадающие id в наборах означают
один и тот же груз с одним названием). `labels` заполняется только FIRS-грузами и нужен
`localiseDot()`: в dot-графе идентификатор узла груза — это лейбл. Так строки не дублируются.
Альтернатива — держать две секции `firs` / `vanilla` — отвергнута: тогда `cargoName()` должна
знать, из какого набора пришёл груз, то есть тянуть `dataset.ts` в модуль перевода.

**Правки поверх источника — отдельный файл с проверкой основания.** `pipeline/ru_overrides.json`:
запись хранит id строки, ожидаемое исходное значение и замену. Если исходное значение не совпало —
экстрактор падает. Так правка не переживёт исправление опечатки в апстриме и не расползётся на
чужую строку. Состав правок (9 записей): регистр — «Кузнечно-литейный Цех», «Стекольный Завод»,
«Магазин Хозяйственных Товаров», «Скотоводеческий Кооператив», «Сталелитейный Завод»; орфография —
«прецезионных» → «прецизионных», «Скотоводеческий» → «Скотоводческий»; буква ё — «Глинозем»,
«Бревна», «Негашеная известь». Лексика источника не меняется.

**Проверка на дрейф — в пайплайне.** `pipeline/validate.py` (или отдельный тест `pipeline/tests/`)
перегенерирует словари в память и сравнивает с закоммиченными. Альтернатива — доверять
дисциплине «не забудь `make data`» — отвергнута: ровно эту ошибку проект уже ловил тестами
на данных.

## Risks / Trade-offs

- **Внешний перевод — чужой репозиторий, может исчезнуть или уехать** → пиним по sha, и
  сгенерированные словари закоммичены: сборка SPA от сети не зависит, страдает только
  перегенерация.
- **Перевод отстанет от следующей версии FIRS** → непокрытые строки попадают в отчёт экстрактора,
  а `locales.test.ts` падает на непереведённом элементе. Тогда решение принимается осознанно
  (дописать правку или подождать апстрим), а не откатывается в английский молча.
- **Смена ключа с лейбла на id — единственное место, где легко потерять названия** → тест на
  полноту по id плюс явный кейс на `WOOD` в обоих наборах.
- **Пользователь, привыкший к нашим формулировкам, увидит другие названия** → это и есть цель
  изменения; расчёт и сохранённое состояние не затрагиваются, откат — вернуть предыдущие словари.
- **Терминология источника местами хуже нашей** (`Steel Plate` → «Стальная пластина») → принято
  сознательно: узнаваемость в игре важнее редакторской точности, см. Non-goals в `proposal.md`.
