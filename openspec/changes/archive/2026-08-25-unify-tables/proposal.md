## Why

Три вкладки показывают списки тремя разными способами: оптимизатор — Mantine `Table` со своим
`SortableTh`, каталог — `mantine-datatable`, снабжение — голую `Table` без рамки. Сортировка
написана дважды и ведёт себя по-разному (три такта против двух, стрелка у активной колонки
против значка у каждой), табличный CSS лежит в двух файлах, а `mantine-datatable` тянет свой
слой каскада, из-за которого правила библиотеки выигрывают у скина по слою, а не по
специфичности. Заход идёт после `align-skin-with-game` и `skin-browser-checks`: оттуда пришли
метрики строки, цвета списка и порядок слоёв, без которых стили таблиц не поддавались скину.

Проверка в браузере на прод-сборке попутно показала, что липкой шапки нет ни на одной вкладке,
хотя правила `position: sticky; top: 0` в CSS есть: `overflow-x: auto` на обёртке заставляет
браузер вычислить и `overflow-y: auto`, так что шапка липнет к контейнеру, который по вертикали
не прокручивается. При прокрутке страницы шапка уезжает ровно на величину прокрутки на обеих
вкладках.

## What Changes

- Общий набор табличных частей в `web/src/components/table/`: обёртка (рамка, горизонтальная
  прокрутка, залипающие крайние колонки, пустое состояние) и `SortableTh`; разметку строк
  каждая страница по-прежнему пишет сама — колоночная модель не выражает шапку оптимизатора,
  где «Движок» и «Вагоны» занимают по две колонки.
- `sortRows` / `nextSort` переезжают из `features/optimizer/sorting.ts` туда же и становятся
  дженериком по типу строки; карта значений колонки остаётся у страницы.
- Каталог переходит с `mantine-datatable` на общий набор: сортировка получает третий такт
  («вернуть год»), значок сортировки — вид оптимизатора (стрелка только у активной колонки, как
  помечает игра), пагинация — `Pagination` из `@mantine/core`, который скин уже красит.
- `mantine-datatable` убирается из зависимостей, из `layers.css` и из правил скина.
- Оптимизатор получает залипающие крайние колонки — при 23 столбцах прокрутка вправо теряла,
  чья это строка. В каталоге ради того же спрайт и название сливаются в одну ячейку под
  заголовком «Название» — строка узнаётся именем, а не картинкой, и в игре пункт списка покупки
  устроен так же.
- Снабжение получает ту же обёртку с рамкой.
- Пустой результат на всех вкладках объясняется сообщением, а не пустой таблицей.
- Мёртвые правила липкой шапки убираются, табличный CSS сводится в один файл; дубль в
  `index.css` перекрыт скином по порядку импорта и вводит в заблуждение.
- Термин **Sort** в `CONTEXT.md` обобщён на все вкладки, решение по библиотеке записано в
  `docs/adr/0003-tables-are-ours-not-a-library.md` (оба файла уже обновлены при разборе).

## Non-goals

- **Липкая шапка.** Чтобы шапка держалась на экране, списку нужна фиксированная высота со своей
  полосой прокрутки. Это ближе к игре (окно списка именно так и устроено), но меняет чтение
  каждой страницы — отдельный заход.
- **Выбор видимых столбцов у оптимизатора.** Ширина решается горизонтальной прокруткой и
  залипающими краями; выбор столбцов — фича с сохраняемым состоянием и своим minor.
- **Свести порционность к одному виду.** У оптимизатора 50 ранжированных строк — листать
  нечего, «показать ещё» правильнее; у каталога 167 отфильтрованных из ~965 — страницы уместны.
  Разнобой продиктован задачей.
- **Игровая модель сортировки** (кнопка «Сортировать по» плюс дропдаун критерия): при 23
  столбцах дропдаун на 23 пункта хуже клика по заголовку.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ui-shell`: как ведёт себя список на любой вкладке — сортировка кликом по заголовку в три
  такта с возвратом к порядку по умолчанию этой вкладки, пометка только активной колонки,
  залипающие крайние колонки при горизонтальной прокрутке, объяснение пустого результата,
  единая рамка списка. Требование про липкую шапку не вводится: её нет и не будет в этом заходе.

## Impact

- `web/src/features/optimizer/OptimizerPage.tsx`, `features/consist/ConsistPage.tsx`,
  `features/industry-supply/IndustrySupplyPage.tsx`; `features/optimizer/sorting.ts` переезжает.
- Новое: `web/src/components/table/`.
- CSS: `web/src/index.css` (табличный блок уходит), `web/src/skin-mantine.css` (правила
  `.mantine-datatable-*` уходят, табличные остаются), `web/src/layers.css` (слой библиотеки
  уходит).
- Зависимости: `mantine-datatable` удаляется из `web/package.json`. Чанк каталога сейчас
  94.7 КБ, из них почти всё — библиотека.
- Тесты: новый визуальный кейс на залипающую колонку и метрики строки; юнит-тесты сортировки
  переезжают вместе с модулем.
- Локализация: новая пара строк для пустого результата оптимизатора в `en.json` / `ru.json`;
  ключи `table.noRecords` и `table.of` переиспользуются.
- Игровых формул и данных изменение не касается — источник истины сверять не с чем; числа в
  таблицах те же.

## Semver

**patch.** Тот же ввод даёт те же числа, настроек и вкладок не прибавляется, сохранённое
состояние не трогается: сортировка и страница каталога живут в локальном `useState`, а
`consistStore` сохраняет только состав и груз. Меняется вид и поведение элементов управления —
это «полировка UI, рефакторинг с теми же числами».
