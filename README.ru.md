# OTTD Tools

**[shkuter.github.io/ottd-tools](https://shkuter.github.io/ottd-tools/)**

*Read this in [English](README.md).*

Калькулятор для OpenTTD с необязательной поддержкой наборов NewGRF Iron Horse (ростер Pony),
xUSSR Railway Set и FIRS 5. Из коробки он считает ванильный OpenTTD: калькулятор ничего не предполагает о твоей
партии, пока ты сам не скажешь — включи наборы в настройках или импортируй сохранённую игру,
и он читает их оттуда.

- **Лучший поезд** — сначала задача, потом поезд: на вход расстояние, длина станции, груз и
  производство предприятия, на выходе перебранный каталог, ранжированный по прибыли, вывозу
  или снабжению, вместе с размером парка и указанием, где помогает «Полная загрузка».
- **Конструктор состава** — собери поезд из полного каталога машин: мощность, сила тяги, вес,
  вместимость, цена покупки, расходы, предельная скорость на равнине и на уклоне
  (реалистичная физика разгона, воспроизведённая по исходникам OpenTTD).
- **Доход рейса** — точное воспроизведение `GetTransportedGoodsIncome` со ставками оплаты FIRS
  и графиком штрафа за время в пути, плюс прибыльность собранного состава на этом маршруте
  (прибыль в год и на тайл поезда, окупаемость).
- **Снабжение предприятия** — все входные грузы одного предприятия разом: парк на каждый вход,
  конверсия, которая из них складывается, и вход, который надо чинить первым.
- **Цепочки FIRS** — интерактивный граф потоков грузов по экономикам (graphviz WASM), карточки
  предприятий и грузов с соотношениями вход/выход.
- **Партия** — импорт сохранённой игры (JGRPP и ваниль; файл читается в воркере и никуда не
  уходит из браузера), из неё калькулятор берёт настройки, поезда, маршруты, станции и
  предприятия. Вкладка показывает твои маршруты: прибыль, которую сама игра записала за
  прошлый год, рядом с прибылью, которую калькулятор ожидает от того же маршрута, — и передаёт
  маршрут или груз на вкладки выше.
- **Настройки** — настройки самой игры из Advanced Settings, названные так же, как в игре,
  плюс допущения калькулятора. Всё есть по-русски и по-английски; названия грузов, предприятий
  и настроек взяты из локалей самой игры и FIRS, поэтому читаешь ты здесь то же, что видишь в
  партии. Интерфейс стилизован под окно OpenTTD и покрашен палитрой OpenGFX2.

## Устройство

- `pipeline/` — экстракторы на Python: импортируют исходники Iron Horse и FIRS напрямую (без
  компиляции NewGRF) и пишут статические JSON в `web/src/data/` плюс иконки грузов в
  `web/public/icons/`. xUSSR — это NML за препроцессором C, поэтому `extract_xussr.py`
  разворачивает его исходники через `cc -E` и читает парсером самого пакета `nml`. `extract_vanilla.py` разбирает и собственные таблицы OpenTTD, поэтому
  калькулятор продолжает работать при любом отключённом наборе, а `extract_opengfx2.py` читает
  GRF базового набора ради ванильных спрайтов и палитры интерфейса. Сгенерированные JSON
  закоммичены, так что веб-приложение собирается без Python.
- `web/` — SPA на React 19 + Vite и Mantine. Игровые формулы живут в `web/src/engine/` как
  чистый TS с тестами vitest; читалка сейвов — `web/src/savegame/`, вкладки —
  `web/src/features/`.
- `docs/` — [ADR](docs/adr/) по решениям, которые заслуживают отдельной записи, и заметки для
  агентов; [CONTEXT.md](CONTEXT.md) — глоссарий. Планирование фич живёт в `openspec/`.
- `vendor/` — shallow-клоны исходных репозиториев (не коммитятся, `make fetch`):
  [iron-horse](https://github.com/andythenorth/iron-horse) — данные о машинах;
  [firs](https://github.com/andythenorth/firs) — данные о предприятиях и грузах;
  [OpenTTD](https://github.com/OpenTTD/OpenTTD) — формулы экономики и физики, локаль;
  [OpenTTD-patches](https://github.com/JGRennison/OpenTTD-patches) — JGR's Patchpack,
  справочник по поведению патчпака, пиннут на релиз, в который играют;
  [xussrset](https://github.com/shkuter/xussrset) — данные машин, путей и вместимостей xUSSR,
  пиннут на форк [George-VB/xussrset](https://github.com/George-VB/xussrset), добавляющий
  метки грузов FIRS 5.2 (предложены апстриму, George-VB/xussrset#257).

## Команды

```sh
make fetch   # клонировать iron-horse (пиннутый тег), firs, openttd, openttd-patches в vendor/
make venv    # venv для Python + Pillow + Chameleon + nml
make data    # перегенерация JSON из исходников в vendor/ + валидация
make data-xussr   # только каталог xUSSR и его русские имена (самая долгая часть)
make check-i18n   # не разъехались ли закоммиченные словари названий с источниками
make data-images  # рендер спрайтшитов Iron Horse + нарезка спрайтов машин, xUSSR тоже
                  # (небыстро)
make data-opengfx2  # ванильные спрайты, иконки грузов и палитра интерфейса из OpenGFX2 Classic
make dev     # dev-сервер vite
make test    # регрессионные тесты пайплайна + тесты формул на vitest
make check-visual  # открыть собранный бандл в браузере и проверить, как отрисован скин
                   # (один раз нужен `cd web && npx playwright install chromium`)
make build   # прод-сборка
make verify  # data + проверка i18n + тесты + проверка отрисованной страницы (со сборкой)
make release VERSION=x.y.z  # закрыть Unreleased в CHANGELOG, бампнуть версию, коммит и тег
make deploy  # перевыложить сайт с текущей ветки (тег v* публикует сам)
```

## Обновление данных

Бампни `IRON_HORSE_REF` / `FIRS_REF` / `OPENTTD_REF` / `OPENTTD_PATCHES_REF` / `XUSSR_REF`
в Makefile, **удали соответствующий клон
в `vendor/`** (`make fetch` пропускает уже существующий каталог), затем
`make fetch && make data && make test`. Регрессионные тесты в `pipeline/tests/` пинуют
эталонные значения (сверены с документацией https://grf.farm/iron-horse/) и покажут
неожиданные расхождения; `make check-i18n` и тесты локалей покажут названия, которые надо
перевести.

## Заметки о точности

- Денежные формулы применяют basecost-шифты GRF, которые задаёт Iron Horse (движки ÷4,
  вагоны ×2, running steam ÷4, дизель ÷16), поверх ванильных базовых цен.
- `price_factor` FIRS → базовая оплата NewGRF: `price_factor × 2^21 / 51000` (конверсия NML).
- Штрафы за время в пути заданы в периодах перевозки по 2.5 игровых дня, а не в днях.
- Длины — в единицах длины OpenTTD: стандартная машина это 8 единиц, то есть полтайла, значит
  тайл — 16 (проверено против игры).
- Инфляция по умолчанию выключена: Iron Horse отказывается загружаться при включённой инфляции.

### Охват xUSSR

Данные покрывают девять GRF, которые набор собирает сегодня (`compile-all.bat`): паровозы,
тепловозы, электровозы, ДМВС, ЭМВС, вагоны, пассажирские вагоны, аддон и рельсы. Числа
извлечены при значениях параметров по умолчанию самого набора, и эти значения записаны в
данные рядом с числами.

Не покрыто:

- **xUSSR Railway Set 0.7.1**, объединённый `xussr.grf` времён до разделения набора. Все его
  машины есть в девяти наборах выше, часто детализированные по годам выпуска (`l150` →
  `l_type1950`, `l_bz_type1946/1947`, `p32_*`), поэтому загруженный рядом с ними он лишь
  показывает каждую машину в меню покупки дважды, причём в более старой ревизии. Импорт сейва
  его распознаёт — партия всё равно считается партией на xUSSR, — но каталог берётся из
  нынешних наборов.
- **Subways Set** и **Ivolga Addon**: исходников для них в репозитории нет. Распознаются при
  импорте сейва, в каталоге отсутствуют.

Механики набора, которые калькулятор не моделирует: падение скорости с возрастом машины,
скорость вагона в зависимости от загрузки и правила составности (нормы сцепки и штраф за их
нарушение). Их отсутствие не искажает остальные числа — каждая из них правило поверх них.

Скорость погрузки — отдельный пробел, и он не про этот набор: её задаёт в данных только
Iron Horse, поэтому круговой рейс на xUSSR и на ванильном ростере считается без стоянки
под погрузку. Сам набор скорости объявляет — у вагонов по грузу и по эпохам, у
пассажирских машин свойством, — так что это число, которое предстоит извлечь, а не то,
которого наборы не дают. На остальные числа рейса это не влияет: стоянка прибавляется к
поездке, а не выводится из неё.
